# Prism vs 四款主流 Markdown 编辑器 · 评委打分报告

> 日期：2026-05-30
> 评测对象：Prism（v1.4.1）对比 Typora、Obsidian、iA Writer、Mark Text
> 评委：Claude（参与 Prism 开发，**非中立**，见下方利益披露）

## 0. 利益披露与方法

**评委不中立。** 本报告作者参与 Prism 开发，天然有倾向。对冲手段有三：先定 rubric 再打分、每个分数给依据、对手方事实尽量查官方/公开来源而非凭记忆。即便如此，主观维度（视觉、手感）仍应打折看待。

**评分对象事实基线（已核实）：**

| 编辑器 | 开源 | 运行时 | 定价 | 维护状态 | 平台 |
|---|---|---|---|---|---|
| **Prism** | 是（MIT） | Tauri（系统 WebView + Rust） | 免费 | 活跃，v1.4.1，重构中 | mac/win/linux |
| **Typora** | 否 | Chromium 系（Electron 族）¹ | $14.99 一次买断 / 3 设备 | 成熟稳定 | mac/win/linux |
| **Obsidian** | 否（核心） | Electron | 个人免费 | 非常活跃 | 全平台含移动 |
| **iA Writer** | 否 | 原生 | $49.99 mac / $29.99 win 买断 | 成熟 | mac/win/iOS，无 Linux |
| **Mark Text** | 是 | Electron | 免费 | **基本停更，末版 0.17.1（2022 初）** | mac/win/linux |

¹ Typora 运行时为架构推断，非官方确认。

**Prism 实现基线（已读代码核实，非规划态）：** 377 源文件 / 142 测试文件。导出四件套（HTML/PDF/PNG/DOCX）+ Pandoc、KaTeX、Mermaid、命令面板、斜杠菜单、浮动工具栏、块级操作、反向链接、关系图谱、Front Matter 面板、10 套模板、5 套内容主题（miaoyan/inkstone/slate/mono/nocturne）、中英日 i18n、自动保存/恢复/冲突，全部**已落地**。`[[` 页面链接**未实现**，Toggle 渲染**部分实现**。

**打分口径：** 1–5 分。出两张表 —— 一张按 Prism 定位加权，一张各维度裸分平铺。性能维度为**架构推断**（未跑基准测试，不编造 MB/毫秒数字）。

**对照解读：**

- **Typora 两表都第一。** 这条赛道里成熟度最高：无缝所见即所得、排印、Pandoc 导出三项满分，久经打磨。Prism 原型对标它是对的。
- **Prism 两表均第四（性能实测后下调）。** 实测后性能从假设的满分 5 降到 4（见下方实测数据），把 Prism 从加权第二拉到第四。它在「写作器真正重要的事」（导出广度、包体小、交互流）上仍强，但内存与大文档渲染并不像架构推断那样占绝对优势。Prism 是**聚焦型选手**而非全能选手。
- **Obsidian 升到两表第二/第二。** 生态（5）和成熟度（5）是其支柱，但这两项对「极简写作器」权重低。强在知识库，不强在「安静写一篇长文」。
- **Mark Text 两表垫底。** 核心拖累是停更（架构 2、成熟度 2）：停在 2022 年的 Electron 老版本、issue 堆积无人理。它反衬出 Prism「活跃维护」的价值。

## 3. Prism 低分归因：故意不做 vs 真实短板

**故意不做（非目标）：**
- **生态扩展（2 分）** — `CONTEXT.md` 明确不做插件系统/市场/第三方 API，与「本地优先单文档写作器」定位一致。
- **知识库/双链宇宙** — 只做轻量关系图谱，不与 Obsidian 拼知识管理。

**真实短板（应补；括号内为 2026-05-30 复核后的实际状态）：**
1. **成熟度（3 分）** — v1.4.1、视觉重构进行中，缺海量真实用户回归。（本轮部分收口：核心写作链路补 e2e，smoke 固化）
2. **`[[` 页面链接** — 复核发现**功能其实已实现**于 `linkCompletion.ts`（触发器+文件/标题/锚点搜索+标准 Markdown 链接插入），原判断有误；真实缺口是接线层类型链路丢失 title/headings，已修复。
3. **Toggle 渲染** — 复核发现预览/CSS/DOCX 降级均已就位，真实缺口是测试与折叠箭头视觉，已闭环（状态升「已实现」）。
4. **导出保真** — 复核发现 `exportPipeline` 已有大量回归覆盖 CONTEXT 硬要求；本轮补集中黄金样本与回归，四格式人工核对待真实 app。
5. **性能** — 本轮已同机实测（见下），并据实把性能分从 5 下调到 4。

## 3.1 性能实测数据（2026-05-30）

> 采集环境：Apple M1 Max / 32 GB / macOS 26.5（25F71）/ Node v25.9.0。Prism release 构建（v1.4.1，aarch64）。
> 竞品对应数字仍为架构推断（未同机实测），仅 Prism 为实测。

**安装包与体积（实测）：**
- DMG 安装包：约 **23.1 MB**（`Prism_1.4.1_aarch64.dmg` = 24,196,330 字节）
- 解压后 `.app`：约 **29 MB**，主二进制（Rust 后端）约 **27 MB**
- 对比：Electron 应用通常 80–150 MB 起步。包体优势属实，**约一个量级**。

**空载常驻内存（实测，单文档空载稳定态）：**
- 主进程（app + Rust）：约 **126 MB**
- WebKit.WebContent（渲染）：约 **238 MB**；WebKit.GPU 约 **81 MB**；WebKit.Networking 约 **13 MB**
- 进程树合计：约 **458 MB**
- 诚实标注：WebKit 系统进程的内存有相当部分与其他 WKWebView 应用共享，不能完全算作 Prism 独占；可确定独占的是主进程约 126 MB。**内存优势没有架构推断暗示的那么大** —— 这是性能分从 5 降 4 的主因之一。

**大文档全量渲染耗时（实测，`markdownToHtml` 中位数）：**

| 文档规模 | 含 KaTeX 公式 | 不含公式 |
|---|---|---|
| 约 1 万行（9411 行 / 244KB） | **2128 ms** | 751 ms |
| 约 5 千行（4707 行 / 121KB） | 992 ms | 288 ms |

- 归因：**KaTeX 渲染占大头**（含公式比不含慢约 1.6–2.8 倍）。markdown 解析本身在 1 万行也要约 750 ms。
- 缓解：实际预览**不是每次按键全量渲染** —— `PreviewPane` 有按文档大小自适应的防抖（小 120ms / 中 220ms / 大文档 600ms）+ `useMemo` 缓存 + `requestIdleCallback` 延迟。所以日常输入手感远好于上面的全量数字，但**大文档单次刷新仍有可感延迟**。
- 这是真实的 React 端大文档瓶颈，已记入 `docs/verification/prism-performance-baseline-2026-05-30.md`，留待后续单独立项（增量渲染 / KaTeX 懒渲染），不在本轮展开重构。


## 4. 分场景结论（不评单一冠军）

| 场景 | 首选 | 理由 |
|---|---|---|
| 最成熟、所见即所得、买断省心 | **Typora** | $14.99 买断，三项核心满分 |
| 知识库/双链/海量插件 | **Obsidian** | 生态成熟度碾压，但非「安静写作」 |
| 极致极简 + 顶级排印 + 原生轻量 | **iA Writer** | 原生最省资源，但贵、无 Linux、功能窄 |
| 开源 + 本地优先 + 占用小 + 导出全 | **Prism** | 唯一同时满足四点；代价是年轻、缺 `[[` |
| 免费开源的所见即所得 | ~~Mark Text~~ → **Prism** | Mark Text 已停更，Prism 是其现代替代 |

**一句话定位：** 在「开源 + Tauri 轻量 + 导出广度 + 活跃维护」交集里，Prism 目前几乎没有正面对手。但拉到「综合成熟度」战场，仍需时间与 `[[`、导出保真的补齐才能进第一梯队。
