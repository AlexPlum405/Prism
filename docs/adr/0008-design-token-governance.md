# 设计令牌治理分层

2026-06-17：Prism 的视觉系统已经从 OpenAI 极简原型和妙言风格单一参考，收束为 ADR-0006 定义的跨平台写作器气质。现有 CSS 中仍同时存在历史核心令牌、过渡别名、主题令牌和局部组件变量。为避免后续 UI 继续混用历史语义，本 ADR 固化当前设计令牌治理方式。

## Decision

Prism 保留 `--c-*` 作为历史核心层和基础真源。虽然这些名称来自 2026-05 的 OpenAI 原型，但在当前代码中已经成为跨平台壳、诊断、状态栏和基础控件的中性色语义层。后续可以调整它们的值和使用规则，但不在本阶段重命名。

过渡别名层包括 `--bg-*`、`--text-*`、`--accent*`、`--stroke-*`、`--elevation-*` 和 `--radius-*`。它们服务旧 module CSS、内联样式、导出背景读取和渐进迁移。新增 UI 不应增加新的过渡别名；迁移时按组件逐步改为 `--c-*`、主题令牌或组件局部变量。

主题令牌层包括 `--theme-*`、`--miaoyan-*`、`--inkstone-*`、`--slate-*`、`--mono-*`、`--nocturne-*`、`--preview-*` 以及 `themeContract.ts` 中的 `editor`、`preview`、`search`、`export`、`code`、`mermaid`、`selection` 契约。它们是内容主题、编辑器、预览、搜索、导出和 Mermaid 的视觉真源。主题专属值应集中在主题文件或契约中，不应散落到普通组件。

组件局部变量层包括 `--compat-*` 等只在组件或兼容模块内定义并消费的变量。它们可以用于降低复杂选择器和重复值，但不能成为跨模块公共 API。若多个组件需要同一语义，应提升到主题令牌或核心令牌。

## Consequences

- 新增 UI 默认使用 `--c-*`、`--duration-*`、`--ease-*`、主题令牌和组件局部变量，不新增 OpenAI-only、Fluent-only 或 AppKit-only token 名称。
- `--bg-*`、`--text-*` 和 `--accent*` 仍可读取既有别名，但不能作为新增设计语义的入口。
- 内容主题新增或调整必须同时更新 `themeContract.ts`、CSS 主题变量、导出/搜索/Mermaid 相关契约，并通过主题测试或截图回归验证。
- 妙言风格仍是重要参考，但 `--miaoyan-*` 不应被当作所有新组件的默认真源；跨主题组件应优先读取 `--theme-*` 或基础 `--c-*`。
- 大规模重命名会带来高视觉回归风险。本阶段只做审计、规则和局部注释收口，后续迁移按组件进行。
