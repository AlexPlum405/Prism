视图切换不一定非要挤在右上角：下面是 5 个能避开「长空白」和「贴着窗口按钮」的方案。

我把三个按钮当作「文档视图控制」，而不是窗口控制。方案 A 直接消掉第二行空白；方案 B 把模式切换放进文档表面；方案 C 借菜单语义收纳；方案 D/E 是更轻的浮动解法。

推荐 A

单行融合标题栏：菜单进标题栏，右侧只保留模式 + 窗口按钮

直接取消下面那条空白菜单带。左侧是 app + 菜单，文档名可收进标题簇或悬停提示，右侧是视图模式，再右侧才是窗口控制。最干净，但需要接受 Windows 上「菜单在标题栏」的现代桌面应用做法。

推荐 B

文档工具条：模式按钮脱离窗口壳，贴到编辑区上沿

标题栏只处理窗口身份和窗口按钮；菜单仍在第二行。视图切换进入 28px 的文档工具条，右对齐到文档区域，不再出现在最小化按钮下方。语义最清楚，但会多一条很薄的内容工具条。

方案 C

菜单语义收纳：三个图标跟在「视图」菜单附近

不放右上，也不贴窗口按钮，而是把它当作「视图」菜单的常用快捷入口。好处是没有孤零零漂在空白条里；坏处是它离右侧编辑/预览结果稍远。

方案 D

编辑区右上浮动：模式切换贴着它控制的内容

把视图切换做成轻浮层，固定在文档画布右上角。它不占 chrome 空间，也不在窗口按钮下方。缺点是滚动和预览内容顶部要留安全区，避免遮住正文。

方案 E

分栏边界浮动：让按钮落在「编辑 / 预览」关系本身上

三按钮悬在分栏中线附近，视觉上解释了「左编辑、右预览、中间分栏」。这是最概念化的方案，适合想强调分栏的 Prism 气质；但对纯编辑/纯预览模式需要重新定位。
